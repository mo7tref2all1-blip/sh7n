# 7. واجهات المستخدم (UI/UX) و Wireframes

> ملاحظة: نظرًا لأن هذه وثيقة تصميم نصية (Markdown)، الشاشات موضحة كـ **Wireframes نصية منظمة** (تخطيط العناصر وترتيب الأولوية البصرية) بدلاً من صور، وهي جاهزة لتحويلها مباشرة إلى تصميم Figma/Adobe XD من قبل مصمم UI/UX. جميع الواجهات **RTL بالكامل** (عربي أولاً).

## 7.1 لغة التصميم العامة (Design System)

- **الألوان الدلالية للحالات** (تُستخدم كشارات/Badges في كل الجداول):
  - أخضر: تم التسليم / محصَّل / معتمد
  - أصفر/برتقالي: قيد التنفيذ / معلّق / بانتظار اعتماد
  - أحمر: مرتجع / لا يرد / رفض / فرق في العهدة
  - أزرق: قيد النقل / جديد
  - رمادي: ملغاة / مؤرشفة
- **الخطوط**: خط عربي واضح لشاشات الإدارة (Cairo/Tajawal)، وخط كبير عالي التباين لواجهة المندوب (استخدام في الشمس/أثناء الحركة).
- **مبدأ "الحالتين معًا"**: أي جدول/بطاقة شحنة يعرض **دائمًا** الحالة التشغيلية والمالية جنبًا إلى جنب (Badge مزدوج) لتجنّب الالتباس الذي هو مصدر أكبر الأخطاء التشغيلية (موضّح في BRD).

## 7.6 واجهة المندوب (Driver PWA) — Mobile-First

تصميم بشاشات كبيرة، أزرار ضخمة قابلة للمس بسهولة أثناء الحركة، أقل عدد ممكن من الخطوات لكل عملية.

│                       │   │                       │   │ أحمد محمد - 01012345  │

- **مؤشر حالة الاتصال**: أيقونة صغيرة أعلى الشاشة تُظهر "غير متصل — سيتم المزامنة لاحقًا" عند العمل Offline، مع عداد للعمليات المعلّقة للمزامنة.
- **زر GPS دائم التفعيل** في الخلفية أثناء "جولة التسليم" النشطة فقط (لتوفير البطارية وعدم انتهاك الخصوصية خارج أوقات العمل).

## 7.7 مبادئ إمكانية الوصول وسهولة الاستخدام (UX Principles)

1. **لا أكثر من 3 نقرات** لإتمام أي عملية متكررة (تسليم شحنة، تسجيل توريد نقدية).
2. **تأكيد صريح قبل أي عملية لا رجعة فيها** (حذف شحنة، اعتماد تسوية) عبر Modal تأكيد يعرض ملخص العملية.
3. **رسائل الخطأ بالعربية الواضحة** وليست رسائل تقنية (مثال: "رقم الهاتف غير صحيح" وليس "Validation Error 422").
4. **الاستجابة الفورية (Optimistic UI)** في واجهة المندوب: تحديث الشاشة فورًا عند أي إجراء حتى قبل تأكيد السيرفر، مع تراجع تلقائي عند فشل المزامنة.
