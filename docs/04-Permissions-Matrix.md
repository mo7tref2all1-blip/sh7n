# 4. نظام الأدوار والصلاحيات (RBAC) ومصفوفة الصلاحيات

## 4.1 مبدأ التصميم

- النظام يعتمد **RBAC هجين**: دور أساسي (Role) + إمكانية استثناءات فردية (`user_permission_overrides`) لكل مستخدم فوق دوره.
- الصلاحيات مقسّمة إلى **وحدات (Modules)**، وكل وحدة بها عمليات (CRUD + عمليات خاصة مثل "اعتماد"، "تصدير"، "تعديل سعر").
- صيغة اسم الصلاحية: `module.action` مثال: `shipments.create`, `settlements.approve`, `wallet.manual_adjust`.
- **مبدأ الحد الأدنى من الصلاحية (Least Privilege)**: كل دور يُمنح فقط ما يحتاجه فعليًا؛ العمليات المالية الحساسة (تعديل رصيد يدوي، اعتماد تسوية) محصورة بأدوار محددة فقط ولا يمكن حتى لـ Super Admin تجاوزها بصمت — أي تعديل يدوي يتطلب **سبب إلزامي مكتوب** يُخزَّن في Audit Log.

## 4.2 قائمة الأدوار

| الدور | الوصف المختصر |
|---|---|
| Super Admin | صلاحية كاملة على النظام بأكمله، بما فيه إعدادات النظام والتكاملات |
| Company Owner | رؤية كاملة (تشغيلية ومالية) + اعتماد القرارات الكبرى (تسعير، تسويات كبرى) |
| Operations Manager | إدارة يومية للعمليات: شحنات، فروع، مندوبين، وكلاء — بدون صلاحيات مالية حساسة كاملة |
| Branch Manager | إدارة فرعه فقط: موظفيه، عهدته، شحناته |
| Customer Service | الشحنات + الشكاوى + التواصل مع التاجر/العميل — بدون وصول مالي |
| Accountant | التسويات، المحفظة، العهدة النقدية، التقارير المالية |
| Merchant (Owner) | بورتال خاص بشركته: شحناته، محفظته، تسوياته، مستخدميه الفرعيين |
| Merchant Employee | نطاق محدود داخل بورتال التاجر حسب صلاحيات يمنحها صاحب الحساب |
| Shipping Agent | بورتال الوكيل: شحناته الموزعة، مندوبيه، تحصيلاته، عهدته |
| Driver | تطبيق/واجهة المندوب فقط: شحناته المخصصة |
| Warehouse Employee | عمليات المخزن داخل الفرع: استلام/تسليم دفعات، جرد |

## 4.4 ملاحظات تنفيذية على النظام

1. **النطاق (Scope Guards)**: كل استعلام Eloquent للأدوار المقيّدة (🔶) يجب أن يمر عبر Global Scope تلقائي (مثال: `BranchScope`, `MerchantScope`) بدلاً من فلترة يدوية متكررة في كل Controller — لتفادي تسريب بيانات بالخطأ.
2. **الصلاحيات الحساسة تتطلب "سبب" (Reason Required)**: أي عملية من نوع `wallet.manual_adjust`, `settlements.approve`, `shipments.delete` تفرض حقل سبب إلزامي في الطلب، ويُحفظ في `audit_log.new_values`.
2.1 **حدود مالية (Approval Thresholds)**: يمكن تحديد حد أقصى لقيمة التسوية التي يعتمدها المحاسب مباشرة (مثال: حتى 50,000 جنيه)، وما فوقه يتطلب اعتماد Owner/Super Admin — يُضبط عبر إعداد نظام قابل للتعديل.
3. **حزمة الصلاحيات الافتراضية قابلة للاستنساخ**: عند إنشاء دور جديد مخصص (Custom Role)، يمكن استنساخه من أقرب دور قياسي ثم تعديله، بدل البدء من صفر.
4. **مصفوفة صلاحيات موظف التاجر (Merchant Employee) ديناميكية**: يحددها صاحب حساب التاجر نفسه عبر شاشة "صلاحيات الموظفين" داخل بورتاله (حقل `merchant_users.permissions_scope` بصيغة JSON)، وليست مصفوفة ثابتة على مستوى النظام — مثال: تاجر قد يمنح موظفه رؤية المحفظة، وتاجر آخر يمنعها تمامًا.
